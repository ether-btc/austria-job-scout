## What Was Done

### 1. `scout_csv_targets()` in `modules/kmu_wien_discovery.py`

The new function takes a path to a single `scout_*.csv` **OR** a directory
containing the three known scout sheets, and returns a list of Target dicts
matching the exact shape produced by `target_discovery.discover()`. Pure —
no network. Sentinels (`nan`, `none`, `null`, `""`, TLDless hosts, scheme
sentinels like `https://nan`) are filtered before URL expansion so the
residential fetch budget is never spent on `https://jobs.nan/`.

Key design decisions:

- **Sheet priority** mirrors the wire-up scratch script:
  `scout_review_required.csv` (1, highest) → `scout_registry_open.csv` (2)
  → `scout_strict_verified.csv` (3, lowest). `max_rows` truncation respects
  this priority — the wishlist is consumed first.
- **Per-domain dedupe** drops the same URL across sheets (was missing in
  the scratch script — the old CSV had implicit duplicates).
- **`source_kind = "kmu_career_url"`** distinguishes these targets from
  Tier-1 ATS (`ats_board`) and aggregator targets in downstream reports.
- **`ats = "generic_html"`** because no ATS is known up front — the
  classifier runs on the response after fetch.

### 2. `discover-kmu` CLI subcommand

Added at `austria_job_scout.cli.cmd_discover_kmu` + parser registration.
Pipeline pattern:

```bash
python -m austria_job_scout discover-kmu \
    --scout-csv /srv/sync/company-recheck-2026-07/scout/ \
    --max-rows 50 \
    --min-relevance 0.4 \
    --out targets.json

python -m austria_job_scout fetch --targets targets.json --max-fetches 25
```

Output JSON has the same `{"targets": [...]}` shape as the existing
`discover` subcommand, so it pipes directly into `fetch`. No translation
step needed.

Flags:

- `--scout-csv PATH` (required): file OR directory
- `--max-rows N`: cap scout rows consumed (each → ~16 URLs)
- `--max-targets N`: cap final output count (post-filter)
- `--min-relevance FLOAT`: drop targets below this score
- `--primary-relevance FLOAT` (default 0.45): first candidate per domain
- `--alternate-relevance FLOAT` (default 0.30): subsequent candidates
- `--out PATH`: write JSON to file (else stdout)

### 3. Tests

`tests/test_discover_kmu.py` — 16 new tests, all green:

- Sentinel filter invariant (the entire point — no `https://jobs.nan/`)
- Target dict schema matches `target_discovery.discover()` output exactly
- Cross-sheet dedupe drops duplicates
- `max_rows` truncation respects sheet priority (wishlist first)
- Directory mode auto-discovers the three known sheets
- Primary/alternate relevance split (1 + 15 per domain)
- Missing optional sheet → silently skipped
- `website` alias header supported (some sheets use it)
- Rows without a name are skipped
- CLI `--help` works, exits 0
- CLI on missing path exits 1 with a clear error
- CLI round-trip: CSV → JSON file → fetch-schema-valid
- CLI `--min-relevance` filter
- CLI `--max-targets` cap
- CLI directory mode
- CLI stdout output is pure JSON (no log noise mixed in)

## Residential-IP Safety Verified

`scout_csv_targets` is **pure** — it does not import `requests`,
`curl_cffi`, `urllib`, or any network layer. The sentinel filter ensures
that even if a malformed scout row slipped through with `https://nan` as
the website field, it would produce zero candidate URLs and burn zero
budget. Pillar 0 + Pillar 0b invariants hold.
